P1. THE MULTI-DATASET NULL — this is the paper's spine. Everything else is support.

a pooled estimate is an external-validity claim, and it converts the paper's single biggest limitation
into its main result. It also makes the h2a non-replication far more interesting: a contrast that
holds on one fold of one screen and nowhere else is a much sharper cautionary tale with ten datasets
behind it than with three folds.

P2. THE DETECTION FLOOR — the sentence that saves the paper from "you just can't measure"
-----------------------------------------------------------------------
COST ~60-100 GPU-h. Run in parallel with P1; it is the second-highest value item.

Every null dies on: "maybe your setup cannot detect anything." The paper currently answers with an MDE
from 5 seeds whose own CI spans 0.005-0.025. Replace it with a measured floor. Inject a known
graph-dependent component into the real DE matrix at a ladder of effect sizes — for each target, add
delta * (mean response of its k-hop PPI neighbours, computed from TRAIN-FOLD RESPONSES ONLY) for delta
in {0, 0.02, 0.05, 0.10, 0.20, 0.40} response SDs — and re-run condition_gated vs expression_only at
n>=4 per rung. Report the smallest delta that reliably clears both corrections.
Then state the null in those units: the benefit, if any, is below a floor you can point at.
LEAKAGE: if the injected signal touches val responses the control is worthless. Write that check as a
test and WATCH IT FAIL before trusting it.
If the floor comes out high, that is also a finding — a limitation with a number instead of a hedge.

P3. THE THREE-WAY ABLATION — 1.8 GPU-h, and it may overturn the framing
-----------------------------------------------------------------------
Do this first; it is nearly free and it tests the paper's own most interesting untested claim.
The paper argues (cause D) that expression_only is NOT graph-free: it gets three PPI degree scalars
(nonzero for 96.5%/98.4% of rows) and a 128-d PINNACLE embedding (real for only 9.2%). Add a
`--drop-graph-features` path (TARGET_SCALAR_KEYS minus ppi_degree_*, zeroed PINNACLE store) and run
five seeds — 0.36 h each — giving:
  (i) no graph information at all   (ii) graph SUMMARY features   (iii) summary + message passing
If (ii) > (i) under correction, the graph DOES help, through node features rather than message
passing, and the field's standard ablation measures the wrong thing. That is a surprising positive
inside a null paper and squarely the Entropic-award shape. If (ii) == (i) the degree scalars are inert
and cause D drops to a footnote. Both outcomes improve the paper.

P4. THE SPECIFICATION SURFACE — turn the re-draw anecdote into a measurement
-----------------------------------------------------------------------
Mostly re-scoring stored predictions, <=40 GPU-h of new training. Enumerate the defensible analysis
choices and compute h1 under every combination: split re-draw seed (3 in hand), metric (systema /
Pearson-delta / program cosine, all computable from stored predictions), checkpoint rule (best-epoch
vs last-epoch), and which arm is called the baseline (expression_only vs untyped_gnn). Plot the
specification curve — sorted estimates with CIs, marked by the choices that produced them — and report
the fraction of defensible specifications in which the graph appears to help, appears to hurt, and
survives correction. Report how many cells are re-scored vs newly trained.
Cite the method properly (specification curve / multiverse analysis) and VERIFY the citations against
primary sources; do not cite from memory.
