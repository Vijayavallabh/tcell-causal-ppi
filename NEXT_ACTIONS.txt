== P1. THE DETECTION FLOOR: prove the pipeline CAN find a graph benefit ====================
COST ~60-100 GPU-h + 2 days build. HIGHEST VALUE. Do this first.

Every null paper dies on one reviewer sentence: "maybe your setup just cannot detect anything." The
paper currently answers with a minimum-detectable-effect calculation from 5 seeds, which is
assumption-laden and whose own CI spans 0.005-0.025. Replace it with an EMPIRICAL detection floor.

Build a positive control. Take the real DE matrix and inject a known, graph-dependent component at
controlled effect sizes: for each target, add delta * (mean response of its k-hop PPI neighbours,
computed INSIDE the train fold only), for delta in a ladder (e.g. 0, 0.02, 0.05, 0.10, 0.20, 0.40 in
units of the response SD). Re-run condition_gated vs expression_only at n>=4 on each rung, same
protocol, same corrections. Report the smallest delta at which the contrast reliably clears both
corrections. That is the pipeline's measured sensitivity.

Then state the null in those units: "the graph benefit, if any, is below the delta we demonstrably
detect." If the floor turns out HIGH (the pipeline is insensitive), that is ALSO a finding and a more
honest paper - say so plainly and it becomes a limitation with a number instead of a hedge.
Leakage discipline: the injected signal must be computed from TRAIN-fold responses only, or you have
built a leak and the control is worthless. Write that check as a test and watch it fail first.
Novelty: empirical sensitivity floors are rare in this literature; most nulls stop at a power formula.

== P2. THE THREE-WAY ABLATION: is the "no-graph" baseline actually graph-free? ===== 1.8 GPU-h ==
COST ~2 GPU-h. Absurd value/cost. Do this immediately, it may run while P1 is being built.

The paper already argues (cause D) that expression_only is NOT graph-free: it receives three PPI
degree scalars (nonzero for 96.5%/98.4% of rows) and a 128-d PINNACLE embedding (real for only 9.2%).
It flags the three-way ablation as future work. DO IT - expression_only costs 0.36 GPU-h, so five
seeds of a stripped variant is under two hours.

Add a `--drop-graph-features` path (TARGET_SCALAR_KEYS minus the three ppi_degree_* entries, and a
zeroed PINNACLE store) and run:
    (i)  expression_only MINUS graph-derived node features   <- the true no-graph floor
    (ii) expression_only as-is (graph summary features)      <- already have n=5 on 3 folds
    (iii) condition_gated (summary + message passing)        <- already have n=5 on 3 folds
If (ii) > (i) and survives correction, the graph DOES help - just through node features, not message
passing - and the field has been running the wrong ablation. That is a genuinely surprising positive
inside a null paper, which is exactly the Entropic-award shape. If (ii) == (i), then the degree
scalars are inert and cause D shrinks; say so and drop the claim to a footnote. Either outcome
improves the paper. Run on all three folds if cheap; at minimum the frozen fold, n=5.

== P3. THE SPECIFICATION CURVE: measure the researcher-degrees-of-freedom surface ==========
COST ~mostly re-scoring + <=40 GPU-h. The most methodologically novel thing available.

You have an anecdote that the verdict flips under a re-draw. Generalise it into a measured surface.
Enumerate the defensible analysis choices a competent researcher could have made, and compute h1 under
every combination: split re-draw seed (3 in hand), metric (systema / Pearson-delta / program cosine -
all already computable from stored predictions), early-stop rule (best-epoch vs last-epoch checkpoint),
and which arm is called the baseline (expression_only vs untyped_gnn). Most cells are RE-SCORING
existing predictions, not new training - do the cheap cells first and report how many cells are real
vs re-scored.

Plot the specification curve (sorted h1 estimates with their CIs, marked by which choices produced
them) and report: the fraction of defensible specifications where the graph appears to help, where it
appears to hurt, and where it survives correction. If, as expected, the corrected verdict is stable
across the whole surface while the uncorrected one is not, you have a quantitative argument for
multiplicity control that has nothing to do with the usual false-positive story - and a figure that
reviewers will remember.
Cite the method honestly: Simonsohn et al. specification curve / Steegen et al. multiverse analysis.
Verify those citations against primary sources before using them; do not cite from memory.

== P4. SIMULATION-BASED POWER, using the variance structure you actually measured ====== CPU only ==
The paper's MDE is a closed-form t calculation on 5 seeds. You now have far better inputs: measured
per-arm across-seed SDs on three folds (no-graph 0.0003-0.0027, graph arms 6-32x that), plus the
re-draw variance component. Run a Monte-Carlo power analysis with that two-level structure (seed
variance nested in re-draw variance) and answer the question a reader actually has: *how many seeds,
and how many independent re-draws, would be needed to detect the benefit that graph-prior papers
report?* If the answer is "more than anyone runs", that is the paper's most quotable sentence.
The statistical-power skill in this repo covers simulation-based designs; use it.
